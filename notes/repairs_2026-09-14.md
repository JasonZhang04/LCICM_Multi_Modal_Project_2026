## Changes made

### 1. Nested CV harness — `src/multimodal_aorta/training/nested.py` (A1)
Per outer fold: outer-test patients are removed **before any supervised fitting**;
inner-OOF base predictions (patient-grouped) train the fusion; bases are refit on the
full outer-training set; only then is the outer test set predicted. Every fitted object
(PCA, scaler, HGB, ridge, alpha) has an ancestry containing outer-training patients only.

GPU branches that cannot be refit on CPU (fine-tuned CXR, ECG CNN) are passed as
`PrecomputedSpec`, and the run records `exact_nesting: false` with the offending
component names — the run can never be silently reported as clean.

### 2. Acceptance test — `tests/test_nested_leakage.py` (A1)
The perturbation test the review asked for: corrupt an outer fold's labels, and that
fold's own predictions must be bit-identical. **Includes a guard-rail test proving the
probe is sensitive** — it does detect the legacy global-OOF construction. 4/4 pass.

### 3. ECG basis regression test — `tests/test_embedding_basis.py` (A2)
Fold-signature probe, calibrated against a synthetic shared basis. Currently `xfail`
on the real artifact; flips to a pass once the ECG branch is rebuilt on a common basis.

### 4. Full-timestamp cohort ordering — `build_episode_cohort.py` (A5)
`StudyTime` is now parsed and both modalities kept at second resolution; eligibility is
strictly `lag < 0` against the recorded echo **time**. `days_before_echo` is now
fractional. Midnight fallback only where `StudyTime` is genuinely absent (conservative:
makes a CXR look earlier, never later). **Requires a cohort rebuild to take effect.**

### 5. Contiguous lag bins — `eval_supporting_episode.py` (A13)
Half-open `[lo, hi)` bins replace inclusive integer bounds, which silently dropped every
episode whose mean lag fell between bins (120 before; far more now lags are fractional).

### 6. Corrected split — `build_temporal_holdout_v2.py` (A3, A4)
Interval-aware: `implied_year = anchor_group_bound + (echo_year - anchor_year)`, assigned
per patient, never per episode. Writes `episode_split_v2.csv` with three honest labels:

- `develop` — 14,192 episodes / 12,500 patients (647 root+, 548 asc+)
- `quarantine` — 1,072 episodes / **968 never-used patients** (40 root+, 38 asc+); locked
- `exploratory_era` — the old anchor-group split, retained **only** so the earlier
  experiment can be described honestly. These patients were used in development.

Cutoff C=2016, no guard band (chosen 2026-09-14). A strict 1-year guard band was tested
and rejected: MIMIC's 3-year anchor intervals put 8,536 patients in the band, cutting
development to 5,730 episodes. The split is therefore a **later-era** split, not a
strictly-ordered one, and must be described that way.

`build_temporal_holdout.py` now raises on run and documents both defects.

### 7. Honest labelling of the holdout run — `train_holdout_final.py` (A6, A14)
`results.json` now carries `model_evaluated`, `is_selected_final_model: false`,
`split_provenance` and a top-level `WARNING`; per-patient predictions are saved
(previously aggregates only).

## Open caveats

- **The quarantine cohort is small** (40 root / 38 asc positives). It supports a
  descriptive transportability check, not precise event-level inference. External
  validation remains the stronger goal.
- `exact_nesting: false` is expected for any run including the fine-tuned CXR or ECG
  branches until those are retrained inside the outer folds.
- A7 (fine-tuned CXR as the comparator) is now computed on the same nested folds, so
  the scientific question is answerable — but the answer is not yet in.

## Results after repair (14 Sep 2026)

### The A1 leak was real but nearly inert

`outputs/final_model_nested_full` vs the old `final_model_episode`, same immutable folds:

| | Old (global-OOF) | Nested | Nested, exact only |
|---|---:|---:|---:|
| Root R² | 0.331 | 0.332 [0.322, 0.344] | 0.326 |
| Asc R² | 0.334 | 0.337 [0.325, 0.350] | 0.318 |
| Root AUROC ≥4 | 0.838 | 0.838 [0.826, 0.851] | 0.830 |
| Asc AUROC ≥4 | 0.830 | 0.831 [0.816, 0.846] | 0.816 |

The leakage path existed and had to be closed, but it was not inflating the headline.
Performance claims survive a correct evaluation. `exact only` = CXR+EHR refit branches
with no precomputed GPU artifacts (`exact_nesting: true`).

### A7: the multimodal claim does NOT survive the strongest baseline

`outputs/a7_comparison/results.json` — identical episodes, identical nested folds,
2,000 paired patient-clustered bootstrap replicates.

| Site | Arm | R² | AUROC ≥4 cm |
|---|---|---:|---:|
| Root | fine-tuned CXR alone | 0.319 | **0.840** [0.828, 0.852] |
| Root | full multimodal | 0.332 | 0.838 [0.826, 0.851] |
| Asc | fine-tuned CXR alone | 0.333 | **0.833** [0.817, 0.848] |
| Asc | full multimodal | 0.337 | 0.831 [0.816, 0.846] |

Paired differences (full − fine-tuned CXR):

| Site | ΔR² | ΔAUROC ≥4 cm |
|---|---:|---:|
| Root | **+0.013 [+0.009, +0.017]** | −0.001 [−0.006, +0.003] |
| Asc | +0.004 [−0.000, +0.008] | −0.002 [−0.006, +0.002] |

**Conclusions.**
1. **No demonstrated ≥4 cm discrimination benefit from multimodality.** Both ΔAUROC
   intervals include zero with negative point estimates. Fine-tuned CXR alone is the
   best discriminator in the project.
2. A **small but statistically clear root R² gain** (+0.013) survives; ascending is null.
3. The **frozen CXR branch is dispensable**: it is worse than fine-tuned CXR on root
   AUROC (−0.011 [−0.019, −0.003]) while doubling the CXR pipeline's complexity.

**Caveat, stated plainly:** the fine-tuned CXR arm is a `PrecomputedSpec`, so its OOF
predictions come from a globally-trained artifact and this comparison is not exactly
nested. That bias would if anything *flatter* the CXR arm — which makes the "no
multimodal AUROC advantage" conclusion more robust, not less. Settling it exactly
requires refitting the fine-tuned CXR inside each outer fold (GPU, Stage 1 of the roadmap).

### What this means for the paper

The honest framing is an **incremental-value study**: on a large hospital cohort, a
fine-tuned CXR encoder alone achieves AUROC ~0.84/0.83 for ≥4 cm, and adding ECG and
EHR yields no discrimination benefit and only a marginal root R² gain. That is a
publishable, well-controlled negative/selective result — and it matches independent
findings (CareBench) that multimodal benefit is task-dependent. It is **not** the
"multimodal superiority" story the current progress report tells.

## A9 — RAD-DINO preprocessing mismatch quantified

The checkpoint's `preprocessor_config.json` specifies grayscale-equal normalization
(0.5307/0.2583), shortest-edge 518 + center crop, bicubic. The pipeline used 224
square-squash with ImageNet **per-channel** normalization. Measured on a real CXR:

| Mode | Shape | Per-channel mean | Channel spread |
|---|---|---|---:|
| `legacy` | (3,224,224) | 0.052 / 0.183 / 0.404 | **0.352** |
| `ckpt_norm` | (3,224,224) | −0.130 / −0.130 / −0.130 | 0.000 |
| `ckpt_full` | (3,518,518) | 0.092 / 0.092 / 0.092 | 0.000 |

A chest X-ray's three channels are **identical by construction**. ImageNet normalization
divides them by three different standard deviations, injecting a spurious colour
gradient (spread 0.352) into every image the encoder sees. This is a real distribution
mismatch, not a cosmetic one.

`load_cxr` now takes `cfg.cxr_preproc` ∈ {legacy, ckpt_norm, ckpt_full}; caches are
mode-tagged so variants cannot overwrite or be silently mixed, and a non-legacy run
**refuses to fall back** to the legacy cache. **`legacy` was verified to reproduce the
existing cache bit-exactly**, so all prior results remain reproducible.

### Separately: horizontal flip disabled
`cxr_aug_hflip_p` was 0.5 — mirroring a CXR moves the heart and aortic arch to the
right side, destroying the left-mediastinal silhouette being measured. Saved results are
unaffected (fine-tuning reads the val-path cache), but any future training run would
have been. Now 0.0 and opt-in.

Job 30884958, `outputs/cxr_finetune_episode_ckpt_norm/`. One factor changed versus the
saved baseline; everything else identical (`SEED=42`, `FT_BLOCKS=2`, same 224 geometry,
same episodes, same folds, same immutable fold file).

Cache verified comparable before launch: identical shape (60091, 3, 224, 224), identical
dicom set, 60,090 ok / 1 fail in both. Channel spread over 200 real cached images:

| Cache | mean spread | max spread |
|---|---:|---:|
| legacy | 0.3500 | 0.3530 |
| ckpt_norm | **0.0000** | **0.0000** |

Baseline to beat (`outputs/cxr_finetune_episode/results.json`):

| Site | R² | AUROC ≥4 cm |
|---|---|---|
| root | 0.319 [0.307, 0.331] | 0.840 [0.828, 0.852] |
| asc | 0.333 [0.320, 0.347] | 0.833 [0.817, 0.848] |

**Prespecified interpretation, recorded before the result is known.** This is a single
seed, so fold-to-fold and seed-to-seed variation are not captured by these CIs alone;
a difference smaller than roughly ±0.01 R² should be treated as inconclusive rather
than as evidence either way, and confirmed with additional seeds before adoption.
A null result is a legitimate outcome: it would mean RAD-DINO's frozen/fine-tuned
features are robust to the channel mismatch, which is worth reporting. It would NOT
retroactively justify the legacy normalization as correct.

If it helps, the next steps are C1 step 2 (resolution/geometry at 518) and then
re-running the A7 comparison against the improved CXR arm — the A7 conclusion is
conditional on the CXR baseline's strength, so a stronger baseline can only widen the
gap the multimodal model has to close.

### A9 experiment C1 step 1 — RESULT: null

`outputs/cxr_preproc_comparison/results.json`. Job 30884958 completed; one factor
differed from the saved baseline (checkpoint grayscale normalization + bicubic vs
ImageNet per-channel + bilinear), same 224 geometry, same seed, folds and episodes.

| Site | legacy R² | ckpt_norm R² | paired ΔR² | paired ΔAUROC |
|---|---|---|---|---|
| Root | 0.319 [0.307, 0.331] | 0.319 [0.307, 0.332] | **0.000 [−0.000, 0.001]** | 0.000 [−0.000, 0.001] |
| Asc | 0.333 [0.320, 0.347] | 0.333 [0.320, 0.347] | **0.000 [−0.000, 0.001]** | 0.000 [−0.000, 0.001] |

**Verdict: no effect.** Not merely "within the inconclusive band" — the paired
differences are zero to three decimals with intervals that exclude anything material.
This is a stronger null than the prespecified band was designed to detect.

**Interpretation, carefully.** The input mismatch was real and large in pixel space
(channel spread 0.352 → 0.000, verified on 200 cached images). It simply does not
propagate to downstream performance here. The most likely reason: the first thing
RAD-DINO's patch embedding does is a learned linear projection over all three channels,
so a fixed invertible per-channel affine transform is something the network — and
especially the fine-tuned last two blocks and the linear head — absorbs trivially.

**What this does NOT license:**
- It does not show preprocessing is irrelevant in general. **Only normalization was
  tested.** Resolution and aspect ratio (224 square-squash vs 518 shortest-edge) are
  untested and are the geometrically meaningful part of the mismatch — an aortic
  silhouette measurement plausibly depends on aspect ratio in a way it does not depend
  on channel scaling.
- It does not mean the legacy normalization was *correct*; it means it was *harmless*
  for this endpoint and this encoder.

**Consequence for the roadmap.** C1 step 1 is closed. The remaining preprocessing
hypothesis is geometric (C1 step 2: `ckpt_full`, 518 + center crop, with a
field-of-view-preserving variant as the control, since the center crop can clip
peripheral anatomy). That is a genuinely different intervention, ~5x the cache size and
meaningfully more GPU time per step.

**Consequence for A7.** The fine-tuned CXR baseline is unchanged, so the A7 conclusion
stands exactly as reported: no demonstrated multimodal AUROC advantage over fine-tuned
CXR alone.
